## 1. Question

What public, documented JSON data sources exist for Marvel Rivals, Path of Exile 2, No More Room in Hell (Steam app 224260) and weather, and what does each allow a free public Discord bot to do? An answer has to give, per source: the capabilities it can honestly back (profile, match history, match detail, ladder/rank, economy, achievements/playtime), authentication, rate limits, terms for a free public bot (attribution, commercial-use clauses, caching, redistribution in Discord messages), whether it is official, versioned and stable. For weather it has to deliver current conditions plus a short forecast with no key, and a geocoder that turns a city name or postal code into coordinates in place of the 4 MB local `res/zip codes.txt`. No HTML scraping.

- **Marvel Rivals: no official API found; one community API (`marvelrivalsapi.com`) covers profile, rank, match history and match detail behind an operator key.** It states it is "non-official" and not endorsed by NetEase or Marvel, lists a free tier of 3,000 requests a day, and its terms could not be read. An honest provider claims `PROFILE`, `MATCH_HISTORY`, `MATCH_DETAIL` (rank sits inside the profile) and ships Experimental. Its achievements endpoints are a catalogue, not per-player data. Tracker Network lists no Marvel Rivals API on its developer page.
- **Path of Exile 2: only `ECONOMY` is honestly available today, from poe.ninja's documented economy endpoints.** GGG's official OAuth API does carry PoE 2 (a `poe2` realm, `/character/poe2`, a ladder scope), but a bot's source records GGG's registration as closed to new applications ("We are currently unable to process new applications") as of 2026-10-14, and every account call needs per-user authorization. poe.ninja's own docs say its profile and build endpoints are not for third parties and that economy access carries no stability promise.
- **No More Room in Hell: a Steam-only provider with `PROFILE`, `ACHIEVEMENTS` and playtime; no match history, match detail or economy exist.** It needs an operator Steam Web API key for every per-user call, so it runs only on a user's own request. - **Provider-model consequences:** a capability can be account-scoped (profile, history) or global (economy, achievement catalogue, weather), the account identity differs per game (Steam64, Marvel Rivals UID or username, PoE account name with a discriminator), four authentication shapes exist (none, operator key header, operator Steam key plus the player's privacy setting, per-user OAuth), and a "ladder" capability exists in two sources but not in the current capability set.

## 3. Findings

Evidence tiers: **consensus** (standard or multiple independent credible sources), **practice** (what mature code visibly does), **single source** (one source, including a service's own code for its own behaviour), **unverified** (a search-tool excerpt of a page whose host could not be opened).

### 3.1 Weather: Open-Meteo forecast API

- **Free tier, limits, non-commercial.** The terms page lists "Less than 10'000 API calls per day, 5'000 per hour and 600 per minute." and "You may only use the free API services for non-commercial purposes." It defines commercial use as "Websites or apps that have subscriptions or display advertisements." and lists "Private or non-profit websites or apps that do not have subscriptions or advertising." and "Voluntary donations, including contributions through a tip jar, are permitted." as non-commercial. Tier: single source (the provider's own terms page, read at source in the website repository). Applies to the site at `7083376`. The server enforces the same figures as defaults (`CALL_LIMIT_DAILY` 10,000, `CALL_LIMIT_HOURLY` 5,000, `CALL_LIMIT_MINUTELY` 600 in `RateLimiter.swift`).
- **Counted per IP and per application.** "Rate limits are applied by IP addresses and application." The terms add that shared hosting providers (Vercel, Netlify, Render, Google Sheets are named) may be limited earlier. Over a limit the server answers HTTP 429 with a reason string such as "Daily API request limit exceeded. Please try again tomorrow." (`RateLimitError.reason`); it sets no `Retry-After` in the code read, so the pause target is the next minute, hour or day. Tier: single source.
- **Calls are weighted, not flat.** `calculateQueryWeight` documents "14 days of data are considered a weight of 1" and "10 weather variables are a weight of 1", scaled linearly, times the number of locations. One location with at most 10 variables over at most 14 days costs 1 call. Tier: single source (server code comment).
- **Licence and attribution.** "API data is offered under the Attribution 4.0 International license (CC BY 4.0)." and "Include an attribution link next to any location where Open-Meteo data is displayed", with the example `<a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>`. CC BY also requires indicating changes (unit conversion and rounding are the changes a bot makes). Tier: single source (README at `7afe0fd`).
- **Not versioned as a product, but additive.** The path is `/v1/forecast`; the geocoding docs promise "no required parameters will be added in the future" (docs page, near the parameter table). Tier: single source. Open-Meteo is community/commercial-hybrid, not a government service; the SLA is none ("All data is provided as-is without any warranty.").
- **Request and response shape.** Parameters read from `static/docs/openapi/forecast.yml`: `latitude`, `longitude`, `current` ("A list of variables to return for the current conditions."), `daily` ("A list of daily weather variable aggregations."), `forecast_days` (default 7, maximum 16), `timezone` ("Any IANA time zone name is supported. Use auto to resolve the local time zone."), `temperature_unit` (`celsius`, `fahrenheit`), `wind_speed_unit` (`kmh`, `ms`, `mph`, `kn`), `precipitation_unit` (`mm`, `inch`). Current variables include `temperature_2m`, `relative_humidity_2m`, `apparent_temperature`, `is_day`, `precipitation`, `weather_code`, `cloud_cover`, `pressure_msl`, `wind_speed_10m`, `wind_direction_10m`, `wind_gusts_10m`; daily include `weather_code`, `temperature_2m_max`, `temperature_2m_min`, `precipitation_sum`, `precipitation_probability_max`, `wind_speed_10m_max`, `sunrise`, `sunset`, `uv_index_max`. The response has `latitude`, `longitude`, `elevation`, `utc_offset_seconds`, `timezone`, a `current` object (`time`, `interval`, scalar variables), `current_units`, a `daily` object of parallel arrays (`time` plus one array per variable) and `daily_units`; errors are `{"error": true, "reason": "..."}`. `weather_code` follows WMO ("Follow WMO weather interpretation codes."). Tier: single source (the provider's OpenAPI file and docs page). The server host is `https://api.open-meteo.com`.
- **Cadence.** The README states "Weather model updates every hour for Europe and North America", so a cache TTL of 10 to 15 minutes for a current-conditions reply is a judgement, not a documented figure.

### 3.2 Weather: geocoding

- **Open-Meteo geocoding** (`https://geocoding-api.open-meteo.com/v1/search`, same terms as the forecast API; the geocoding repository README restates the "10'000 requests per day" fair-use line). Parameters: `name` ("Location name or postal code. Append a country or first-level administrative area after a comma to narrow the results."), `count` (default 10, 1 to 100: "Parameter count must be between 1 and 100."), `language` (the docs list `en`, `de`, `fr`, `es`, `it`, `pt`, `ru`, `tr`, `hi`), `countryCode` (ISO 3166-1 alpha-2), `format` (`json` or `protobuf`). Matching: "Two characters match an exact name. Three or more use normalized prefix matching."; the qualifier "must match exactly; partial and prefix matching are not supported" (for example `Los Angeles, CA` or `Paris, France`). A result has `id`, `name`, `latitude`, `longitude`, `elevation`, `feature_code`, `country_code`, `admin1` to `admin4`, `timezone`, `population`, `postcodes`, `country`. Tier: single source (docs page, `geocoding-object.svx`, controller). Data comes from GeoNames ("location search using GeoNames source data").
- **Postal codes.** The docs section is titled "Search for cities or postal code". The repository's `GeocodingDatabaseTests` search for a postcode `"1234"` and expect the place that carries it (`#expect(postcode.map(\.id) == [120])`), and the builder takes postcodes from GeoNames alternate-name rows of language `post`. So postal search works by design; **how many countries' postcodes are in the GeoNames alternate-name data, and whether US ZIP codes such as `90210` resolve to one place, was not testable** (host unreachable). The old `res/zip codes.txt` is US-only (columns `zip`, `primary_city`, `state`, `latitude`, `longitude`), so US ZIP coverage is the acceptance test for the replacement. Tier: single source; coverage unverified.
- **Licence inconsistency to note.** The geocoding repository README says "API data are offered under Attribution-NonCommercial 4.0 International (CC BY-NC 4.0)", while the website terms and the forecast README say CC BY 4.0. Both are met by non-commercial use plus the "Weather data by Open-Meteo.com" link; the discrepancy is a re-check item. GeoNames' own credit requirement is not mentioned in Open-Meteo's terms and was not read.
- **Zippopotam.us (fallback candidate).** A search excerpt of its docs says there is no authentication, no signup, the route is `/{country}/{postalCode}` on `https://api.zippopotam.us`, data is from GeoNames "as-is", and "no hard limits"; it publishes no formal terms or numeric limit. Tier: unverified (docs host unreachable). Would only be a postal-code fallback behind the same geocoder port.
- **Nominatim (OpenStreetMap), comparison only.** A mirror of the OSM usage policy in a search excerpt lists "an absolute maximum of 1 request/s", a valid identifying User-Agent or Referer, attribution, and discourages bulk geocoding. Tier: unverified (policy host unreachable). Not chosen: a stricter limit and a bulk-use warning, with no postal-code advantage established.
- **MET Norway and the NWS publish no geocoder.** MET Norway's FAQ: "You need a geocoding service." (it suggests GeoNames or Nominatim). The NWS FAQ: "Our API does not offer a geocoding service." and lists commercial and Census options. Tier: single source each (their own docs).

### 3.3 Weather: other free no-key forecast services

- **MET Norway `api.met.no` Locationforecast 2.0** (`/weatherapi/locationforecast/2.0/compact?lat=&lon=`; formats `classic`, `compact`, `complete`). No key. Terms (docs repository, `doc/TermsOfService.md`, page dated 2020-06-26): identifying User-Agent ("All requests must (if possible) include an identifying User Agent-string (UA) in the request"; the HowTo adds "If this is missing or generic, you will get a `403 Forbidden` response."); coordinates truncated to 4 decimals ("truncate all coordinates to max 4"; five or more decimals return 403 for new products); honour `Expires` and use `If-Modified-Since`; "Anything over 20 requests/second per application (total, not per client) requires special agreement."; throttling is HTTP 429; deprecated versions answer 203; attribution per CC BY 4.0 plus NLOD 2.0 (`doc/License.md`: credit "MET Norway", for example "Data from MET Norway"); no SLA; do not use "Yr" in a service name. Tier: single source (provider's own docs, but the repository's last commit is 2023-03-07 and the live site was not read). Verdict: credible, European-quality data, but it needs a separate geocoder, has stricter etiquette, and returns hourly series that the bot must reduce to a daily forecast itself.
- **US National Weather Service `api.weather.gov`.** No key; requests need a `User-Agent` ("We recommend setting the value to something that identifies your application and includes a contact email"); the FAQ warns "In the future we will replace the User-Agent requirement with a more typical API key system."; two calls per lookup (`/points` then the grid forecast). US-only. Tier: single source (docs repository at `694ed0f`, 2024-05-08). Not chosen: a public bot is not US-only.

### 3.4 Marvel Rivals

- **Official API: none found.** No NetEase or Marvel developer documentation turned up in search, and `developer.marvelrivals.com`, `www.marvelrivals.com` were unreachable. One tutorial (via search) says NetEase "has not published a fully open official stats API". Tier: unverified; absence of evidence, not a statement from NetEase.
- **Tracker Network.** The `tracker.gg/developers` page, as returned by a search excerpt, lists an Apex Legends, CSGO, Division 2 and Splitgate stats API (and Bloodhunt) and says the company "is working hard to expand this list"; no Marvel Rivals API and no application procedure appeared. Tier: unverified (host unreachable; the page is undated). The only `tracker.gg` Marvel Rivals material found is a scraper actor, which is HTML scraping and is excluded.
- **Community API `marvelrivalsapi.com`.** Self-described: "non-official API and not endorsed by NetEase Games or Marvel Entertainment in anyway" (search excerpt of the site, unverified). Authentication: key in an `x-api-key` header (read at source in the wrapper: `"x-api-key": `${apiKey}``). Docs at `docs.marvelrivalsapi.com` (unreachable); search excerpts: "Once you have your key, include it in the x-api-key header of every request.", a free "Basic" plan "$0 / month ... 3,000 requests / day" and a 20,000-a-day plan (unverified), and "dynamic rate limit that adjusts to each user" with a 429 on excess. The player-refresh endpoint "can only be used every 30 minutes on 1 specific player" (unverified). A second site, `test.rivalsdb.info`, shows different plan numbers; ignore it.
- **Endpoints, read at source** (the official-labelled Node wrapper at `d6927e6`, `lib/endpoints/*.js`, base `https://marvelrivalsapi.com/api/`): `v1/find-player/{username}`, `v1/player/{query}` and `v2/player/{query}` (stats; `query` is a UID or a username; season filter), `v1|v2/player/{query}/update` (refresh), `v2/player/{query}/match-history` (filters: `season`, `page`, `limit` default 40, `skip`, `game_mode`, `timestamp`: "Only includes matches after the given timestamp"), `v1/match/{match_uid}`, `v1/heroes`, `v2/heroes`, `v1/heroes/leaderboard/{hero}?platform=`, `v1/achievements`, `v1/patch-notes`, `v1/maps`, `v1/items`. The Python wrapper (`externref/marvelrivalsapi`, `models.RankSeason`) models rank as a per-season object with `level`, `rank_score`, `max_level`, `max_rank_score`, `win_count`. So **profile, rank, match history, match detail, hero leaderboards, patch notes and static catalogues** are all reachable. Tier: practice (two independent wrappers agree on routes), content of responses not observed.
- **Achievements are a catalogue.** `v1/achievements` and `v1/achievement/{id}` take a `query`/`page`/`limit`, no player; they list what exists in the game, not what a player has unlocked. A per-player `ACHIEVEMENTS` capability is therefore not backed.
- **Stability.** v1 and v2 of the player and match-history routes both exist at once (the wrapper carries both: `player.js` and `playerv2.js`, `matchhistory.js` and `matchhistoryv1.js`); the Node wrapper has 5 commits, no releases and a request helper copied from another API (its `deprecatedEndpoints` table names "invoices" and "listings", which this API does not have); the Python wrapper's last commit is 2025-05-09; the username lookup is described in the docs as "a new feature and is not always reliable" (excerpt) against UID lookup as "more stable". An MCP server found in search points at a different host (`marvelsapi.com`), so the ecosystem is fragmented. Tier: practice.
- **Where the data comes from is not stated** (the "update" endpoint and 30-minute limit suggest the service pulls from the game's backend on demand; that is an inference, not a documented fact). The risk that upstream access changes without notice is therefore the provider's, not the library's.

### 3.5 Path of Exile 2

- **GGG official API (OAuth 2.1).** From the authorization docs (search excerpts, unverified): "Almost all of Path of Exile's developer APIs require authorization of an existing Path of Exile account to use."; "We implement the OAuth 2.1 standard"; a client-credentials grant for data not tied to an account; and a stability warning, "The details in this document may change without notice as they adjust to protect their backend from being overloaded. They make no guarantee that API endpoints will remain available indefinitely." An identifying User-Agent beginning with the OAuth client id, a version and a contact is required (`poe2-mcp` `userAgent()` comment: "GGG requires every OAuth client to send a descriptive User-Agent that identifies the application and a contact"), and public applications are asked to say they are not affiliated with GGG (excerpt, unverified). Rate limits are dynamic and header-declared (see `http-client-stack.md`, F6).
- **PoE 2 coverage.** A search excerpt of the reference lists `GET /league/<league>/ladder` with scope `service:leagues:ladder` and a `realm` parameter that "accepts pc (the default), xbox, sony, or poe2", with a `sort` parameter "PoE1 only", and a note that "there are currently limited APIs that return PoE2 game information". A bot targets `GET /character/poe2` and `GET /character/poe2/<name>` with scopes `account:profile` and `account:characters` (`rpeters1430/poe2-mcp`, `src/auth.ts` and `src/adapters/ggg-api.ts`, "per GGG's published reference"), and the data is "account-sheet data (refreshed on request)", not live combat. So PoE 2 **profile/characters and ladder exist in the official API**; economy and match history do not. Tier: unverified for the endpoint list (the reference was unreachable); practice for the character routes and scopes (one bot's working code and README).
- **Registration is the blocker.** `poe2-mcp`'s README states: "GGG's OAuth application registration is closed to new applications as of this writing ("We are currently unable to process new applications") — see `pathofexile.com/developer/docs/index`" and names a staff-suggested contact address, with no confirmed turnaround. A second project (`poe2-forge`, 2026-09-11) records the same: "OAuth registration status unverified; direct character import unavailable." Tier: single source quoting GGG's page at 2026-10-14; the docs page itself was unreachable. Even with a client id, character access is per user (authorization-code flow, refresh tokens that the bot's comments say "may have expired after 90 days"), which needs a web callback a Discord bot does not otherwise have.
- **poe.ninja economy.** The API reference at `poe.ninja/docs/api` (search excerpt, unverified) says "The economy overview endpoints documented on this page are the supported public surface of the poe.ninja API. They cover economy pricing for Path of Exile 1 and Path of Exile 2.", that "Public access to the economy endpoints is allowed but incidental", that "supported" means "you are allowed to use it, not that it is stable", that there is no versioning and no SLA, and that clients making excessive use "will be blocked"; the leagues route is `GET /poe2/api/economy/leagues`. A browser extension's README (`poe-ninja-build-cost` @ `06ef03e`) quotes the same page: "The builds / profiles API, and every other non-economy endpoint (character, Path of Building, authentication), are internal. They are undocumented, unsupported, and not available for third-party use." It also notes that poe.ninja "asks for a descriptive User-Agent identifying the app and a contact" and that a non-ASCII User-Agent gets a 403. Tier: practice (a 2026 project quotes the page) and unverified at source.
- **PoE 2 route in use.** `sergeyklay/poe2-mcp-server` calls `https://poe.ninja/poe2/api/economy/exchange/current/overview?league=<name>&type=<category>` (`NINJA_POE2_BASE`, `getNinjaExchangeOverview`; example categories "Currency", "Fragments", "Essences"). An older write-up (`Davenads/poeninjaAPI-2025`) shows `/poe2/api/economy/currencyexchange/overview` with `leagueName` and `overviewName`, a 12-requests-per-5-minutes figure and "may change without notice". Two routes in a year is the instability the docs warn of. Tier: practice; the current exact route is unverified.
- **What PalOfExile wanted.** `PalOfExile.kt` screenshots `https://poe.ninja/challenge/currency/<name>` and crops the price box for currency, shards and oils (PoE 1), and has a wiki-lookup stub. A documented economy JSON response replaces the screenshot with typed fields (price, listings); the PoE 2 wiki lookup was not researched.

### 3.6 No More Room in Hell (Steam app 224260)

- **Interfaces, from Valve's published interface list** (`SteamTracking` @ `f885c90`). Per-user methods all require `key`: `ISteamUserStats/GetPlayerAchievements` (`key`, `steamid`, `appid`, optional `l`), `GetUserStatsForGame` (`key`, `steamid`, `appid`), `GetSchemaForGame` (`key`, `appid`, optional `l`), `IPlayerService/GetOwnedGames` (`key`, `steamid`, `appids_filter`, `include_appinfo`, `include_played_free_games`, ...), `GetRecentlyPlayedGames` (`key`, `steamid`, `count`), and `ISteamUser/GetPlayerSummaries` v2 (`key`, `steamids`, up to 100). **Keyless**: `GetGlobalAchievementPercentagesForApp` (`gameid`), `GetNumberOfCurrentPlayers` (`appid`), `GetGlobalStatsForGame`. Tier: single source (a daily capture of Valve's `GetSupportedAPIList`; Valve's own docs unreachable).
- **Free games are hidden by default.** `GetOwnedGames`: "Free games are excluded by default.  If this is set, free games the user has played will be returned." The game is free to play on Steam (store excerpt, unverified), so playtime needs `include_played_free_games` (and `appids_filter=224260` to bound the reply). `GetRecentlyPlayedGames` carries two-week playtime without that flag.
- **What the game publishes.** Achievements, certainly: the Steam community page reports 115 achievements for the base game (search excerpt, unverified), many of them counters ("Get 250 kills with the Sledgehammer", a kill-count goal in the millions) and a "100% Complete!" meta achievement. Whether the game also defines Steam *stats* (named integer counters that `GetUserStatsForGame` returns beyond the achievement flags) could not be observed; `GetSchemaForGame` for this app was not reachable. No match history, match detail, ladder or economy source exists; third-party sites found (Steambase, SteamDB-style) show only concurrent-player counts. A successor game, No More Room in Hell 2, is a separate Steam app (292000 appears in search results) and is not covered.
- **Key and terms.** The key is operator-held and confidential. From the Steam Web API Terms of Use as carried in `dota2-data-sources.md` (claim 17, unverified at source): a limit of 100,000 calls a day, key kept confidential, "You will only retrieve Steam Data about a Steam end user as requested by the end user", and Valve may change or end the API. Registration reportedly asks for a domain name and a funded account (per secondary guides). Valve's wiki says data may be hidden when a profile is Friends Only or Private (search excerpt); a profile with private game details is therefore an expected outcome (an empty or error result) for achievements, stats and playtime.
- **Consequence.** Because the terms limit retrieval to what the end user requests, the NMRIH provider runs on commands only (no tracker loop). Account identity is the Steam64 id already handled for Dota 2; a vanity URL needs `ResolveVanityURL` (key required).

### 3.7 Attribution in Discord embeds

- The Discord embed author structure has a `url` ("url of author (only supports http(s))") and the title has a `url`; the footer structure has `text`, `icon_url` and `proxy_icon_url` and its reference does not say that markdown links render. Tier: single source (Discord API docs, `developers/resources/message.mdx` at `fd75e22`). A credit that must be a link (Open-Meteo, MET Norway) therefore goes where a link is guaranteed: the embed author line with its `url`, the title link, or the description or a field value.
- The Dota 2 provider uses a footer or description credit with a link (see `dota2-data-sources.md`). The same pattern applies: provider name plus link in the same embed, never a bare statement.

## 4. How comparable projects do it

- **Wrapper libraries as the de facto provider API.** `MarvelRivalsAPI-Wrapper` (Node, MIT) exposes one class per endpoint family (`playerStats`, `matchStats`, `heroes`, `heroesv2`, `matchHistory`, `patchNotes`, `achievements`) over a single `makeRequest(url, params, body, method, apiKey)`; the Python wrapper has sync and async clients and typed `Model` classes (`RankSeason`, `PlayerInfo`, `LeaderboardPlayer`). Both inject the operator key as `x-api-key`. Versions v1 and v2 are separate classes.
- **PoE2 tools split data by source, not by game.** `poe2-mcp` combines three independent sources: GGG OAuth (`ggg-api.ts`), poe.ninja character data and Path of Building exports, and a public GGG skill-tree export (`grindinggear/poe2-skilltree-export`, an unauthenticated file), and records that OAuth is the only blocked path; `poe-ninja-build-cost` calls only the documented economy routes and reads profile data from the page the user already has open to avoid the unsupported endpoints. `sergeyklay/poe2-mcp-server` rate-limits poe.ninja with a built-in limiter (`ninjaLimiter`).
- **Open-Meteo consumers.** The README lists mobile and web apps that call the API with `latitude`/`longitude` from the geocoder; the geocoder's `countryCode` and `, <admin1>` qualifier are the documented ambiguity controls. MET Norway's HowTo describes a complete client lifecycle (identify, honour `Expires`, `If-Modified-Since`, store `Last-Modified`) which maps onto a Caffeine cache with a per-entry expiry.
- **Multi-game stat bots.** No open-source multi-game Discord stats bot with a provider abstraction was found in the sources read; the Marvel Rivals bot visible on top.gg exposes `/match history (username) (season) (gamemode)`, which is the community API's own filter set. The provider shape here is therefore derived from the sources' differences, not copied.
- **Old code in this repo.** GKB2's `WeatherCommand` and `Converter` read `res/zip codes.txt` on every call (`readLines()` of the whole file, `startsWith` for ZIP, `contains` for city, first hit wins), reply with raw "lat/long" and never call a forecast API; the replacement is both a geocoder and a forecast provider.

## 5. Pitfalls and regrets

- **Open-Meteo's free tier is non-commercial by definition.** A subscription, premium tier or advertising on the bot's output would put it in the commercial category ("Websites or apps that have subscriptions or display advertisements"); the library must keep the base URL and a key configurable (the paid host is `customer-api.open-meteo.com`, named in the OpenAPI file) so a commercial deployment can switch without code changes. Donations and a tip jar are allowed.
- **Per-IP counting.** Hosting behind a shared outbound IP shares the quota, and the terms name hosts that are limited earlier. Cache aggressively (geocodes for days, forecasts for minutes).
- **Weights, not calls.** Asking for many variables or a long range raises a request's weight above 1; a short forecast stays within 10 variables.
- **City names are ambiguous.** The geocoder returns up to 100 candidates; a bot that always takes the first replicates the old `contains(...)[0]` bug. Offer a disambiguation (country, admin1) when the top results differ.
- **Postal codes without a country are ambiguous across countries**, and coverage is unverified; give the user a clear "add a country" failure instead of a wrong place.
- **MET Norway blocks silently.** A missing or faked User-Agent gets 403 or a permanent ban; coordinates with five or more decimals are refused; polling on the hour is discouraged. If it is ever added, the transport needs per-host User-Agent and coordinate truncation.
- **Community API churn (Marvel Rivals).** v1 and v2 coexist, username lookup is flagged unreliable, the host's terms are unread, and the data's upstream is undocumented. A provider that auto-posts matches multiplies calls per tracked player against a 3,000-a-day shared key; the 30-minute per-player update limit suggests data may not refresh faster than that.
- **GGG documents instability.** "May change without notice"; registration closed; per-user OAuth; header-declared rate limits. A PoE 2 profile feature built now would be built on access that cannot be obtained. poe.ninja's economy "supported" status is explicitly not a stability promise, and two different PoE 2 routes were seen in a year.
- **Steam privacy and the key.** Per-user Steam calls fail for profiles with private game details; a public bot must show that outcome as "make Game details public", not as an error. The Steam key must stay out of background loops by the terms.
- **Free-to-play playtime vanishes by default** (`include_played_free_games`).
- **Do not claim achievements for Marvel Rivals** from a catalogue endpoint, or match history for NMRIH from nothing.

## 6. Recommendation for this repo

**Weather.** Ship one weather plugin with two ports and Open-Meteo as the default implementation of both: a `Geocoder` (query string plus optional country and language, returning candidate places with coordinates, timezone, country, admin1) and a `WeatherProvider` (coordinates plus units, returning a typed current-conditions object and a 5-day daily list). Request `current` and `daily` in one call (about 8 current and 6 daily variables, which stays near weight 1), `timezone=auto`, `forecast_days=5`, and let the guild or user choose units, which the API converts (`temperature_unit`, `wind_speed_unit`, `precipitation_unit`). Wire types are `internal @Serializable` with parallel `List<Double?>` arrays zipped into domain objects and `ignoreUnknownKeys`; a `WeatherCode` sealed hierarchy maps WMO codes to a description and an emoji, with an `Unknown(code)` case. Lookups that can miss return `Result` with distinct failures: `NoMatch`, `Ambiguous(candidates)`, `RateLimited(pause)`, `UpstreamError`. Cache geocodes for days (Caffeine, key = normalised query, country, language) and forecasts for 10 to 15 minutes, both behind the shared per-provider budget. Credit "Weather data by Open-Meteo.com" as a link in the embed author line (with `url`) or the description, and keep the base URL and optional key configurable for a deployment that ever becomes commercial. Ship the old `getcity` and `getzip` as `!` aliases onto one `weather` command that takes either a name or a postal code. Add an opt-in live check at implementation for `90210`, `10001`, `SW1A 1AA`, `75001` and a few ambiguous city names; if US ZIP codes do not resolve, add a `Geocoder` implementation over `api.zippopotam.us` (US lookup) behind the same port. Reject MET Norway and the NWS for the first release: MET needs a separate geocoder and stricter etiquette, and the NWS is US-only. The obvious option of keeping a bundled zip file is rejected: it is US-only, 4 MB, and read in full on every call.

**Marvel Rivals provider (its own phase, Experimental).** `MarvelRivalsProvider` over the community API with the operator key supplied through configuration, claiming `PROFILE` (with rank), `MATCH_HISTORY` and `MATCH_DETAIL`, and nothing else. Keep it on demand until the data's freshness and the key's real daily limit are measured; automatic match posts are not offered. The first-phase research should open `docs.marvelrivalsapi.com` and the site's terms before any code. The privacy policy names this third party. No official source exists, so it must be isolated behind the provider SPI so it can be replaced or dropped.

**Path of Exile 2 provider.** `ECONOMY` only, from poe.ninja's documented economy endpoints (leagues plus exchange overview), with a descriptive ASCII User-Agent and contact, a conservative budget, and a long cache; the capability set then needs no account link for it. Plan `PROFILE` and a ladder capability only if GGG reopens registration and a callback endpoint exists; that is not scheduled and should not shape the 1.0 SPI beyond allowing a capability that needs no link and a different authentication scheme.

**No More Room in Hell provider.** `ISteam`-based, requires an operator Steam key (the provider registers only when a key is configured), claims `PROFILE` (persona from `GetPlayerSummaries`, playtime from `GetOwnedGames` with `appids_filter=224260` and `include_played_free_games`) and `ACHIEVEMENTS` (`GetPlayerAchievements` merged with `GetSchemaForGame` and the keyless global percentages), plus a stats subcommand only if the schema shows game stats. It does not claim match history, match detail or economy, and it runs on commands only. Reuse Dota 2's Steam64 `AccountRef` for the link, with the same optional-vanity rule.

**Shape the provider model has to take.** Four things differ across these sources and the model must not hard-code Dota's answer: (1) a capability is account-scoped or global, so `ECONOMY` (PoE 2) and the achievement catalogue need no link while `PROFILE` does; (2) account identity is a sealed set (Steam64, Marvel Rivals UID or username, PoE account name with discriminator), validated by the provider that owns it; (3) authentication is per provider (none, operator header key, operator Steam key, per-user OAuth), and a provider that cannot be authenticated at start-up is simply not registered; (4) several sources have a season or league dimension (Marvel Rivals `season`, PoE league), so a capability call carries an optional season/league parameter. If a ladder or rank-board subcommand is wanted, the capability set needs a `LADDER` member, because two sources (GGG's ladder, Marvel Rivals hero leaderboards) offer it and no current member covers it.
