## 1. Question

What public, documented JSON data sources exist for Marvel Rivals, Path of Exile 2, No More Room in Hell (Steam app 224260) and weather, and what does each allow a free public Discord bot to do? An answer has to give, per source: the capabilities it can honestly back (profile, match history, match detail, ladder/rank, economy, achievements/playtime), authentication, rate limits, terms for a free public bot (attribution, commercial-use clauses, caching, redistribution in Discord messages), whether it is official, versioned and stable. For weather it has to deliver current conditions plus a short forecast with no key, and a geocoder that turns a city name or postal code into coordinates in place of the 4 MB local `res/zip codes.txt`. No HTML scraping.

Requirements the answer has to meet, stated as facts about the work: the later games follow Dota 2 one per release, each offering only what its source supports and each opening with a fresh look at its sources. Marvel Rivals is an Experimental, on-demand provider over a community API (profile with rank, match history, match detail; no automatic posts). Path of Exile 2 is economy data only, from poe.ninja; profiles and ladders wait for Grinding Gear Games (GGG) to reopen application registration. No More Room in Hell is profile, playtime and achievements through an operator Steam key, on commands only. MagicBot's privacy policy and terms name the third parties whose data it uses. A game whose only public data is achievements or playtime still gets a provider with the subcommands its capabilities allow.

- **Unfinished — needs a planner re-pass: the Marvel Rivals community API's plan table, free-tier size and any terms page; unreachable: `marvelrivalsapi.com` (HTTP 502 on `/`, `/pricing`, `/terms`, `/privacy`, `/api/v1/maps`) and `tracker.gg` (403, Cloudflare challenge).** The API's documentation host answers and was read in full, so its unofficial status, authentication, response shapes and the player-refresh limit are established; the marketing site that holds pricing and any terms of service is not. This does not block the design, because the Marvel Rivals phase opens with its own fresh look at the source, but no free-tier number below is verified. No requirement in the work list fails on what was read.
- **Weather: Open-Meteo for forecast and geocoding is confirmed usable by a free, ad-free bot.** No key; the free tier is "non-commercial" with fewer than 10,000 calls a day, 5,000 an hour and 600 a minute, counted per IP; the data is CC BY 4.0 with a mandatory visible "Weather data by Open-Meteo.com" link, and the licence page also credits GeoNames (CC-BY). The live forecast call returns `current` plus `daily` in one response and no quota or rate-limit header. **The geocoder resolves US ZIP codes** (90210, 10001, 94105 each return the right US place) **and French codes** (75001 returns Paris) **but not UK full postcodes** ("SW1A 1AA" returns nothing; the outward code "SW1A" does) **and not a German code** ("10115" returns a New York hit, not Berlin). Postal codes without a country collide across countries (10001 also matches Cáceres and Troyes; 75001 also matches Addison, Texas). A country-qualified postal fallback exists in Zippopotam.us (`/{country}/{code}`, no key, "no hard limits", GeoNames data, no formal terms).
- **Marvel Rivals: no official API exists; the one community API (`marvelrivalsapi.com`) backs profile with rank, match history and match detail behind an operator key.** `www.marvelrivals.com` carries no developer or API link and `developer.marvelrivals.com` does not resolve. The community API's own documentation says it is unofficial and "was not explicitly made usable by their entities for third parties", states a "dynamic rate limit" with `X-RateLimit-*` headers, a 30-minute lock per player on its refresh endpoint, and tags some endpoints "Premium"; the documentation contains no attribution, caching or redistribution clause. Achievements are a catalogue, not per-player data.
- **Path of Exile 2: `ECONOMY` is the only capability a bot can obtain today; GGG registration is closed.** GGG's developer page says "We are currently unable to process new applications." The official API does carry PoE 2 (`realm=poe2` on leagues and the ladder, which has served the top 1,000 since 0.5.0; `GET /character/poe2`), but every account call and the ladder need an approved application, and the ladder needs a confidential client (an HTTPS callback on a registered domain) with the client-credentials grant. Two documented keyless economy sources exist: poe.ninja's economy endpoints (item and currency prices for PoE 2, "allowed but incidental", no SLA, descriptive User-Agent asked for) and GGG's own public Currency Exchange CDN feed (hourly, currency pairs only, historical).
- **No More Room in Hell: a Steam-only provider with `PROFILE`, playtime and `ACHIEVEMENTS`; no match history, match detail, ladder or economy source exists.** The game is free to play with 115 achievements. Valve's terms allow a user key (anyone with a Steam account and a domain name), a limit of 100,000 calls a day, a privacy policy, retrieval "only ... as requested by the end user" (so commands only) and no implied Valve endorsement. Whether the game defines Steam stats beyond achievements cannot be settled without a key; global stats need a publisher key and the community page lists no public leaderboards.
- **Provider-model consequences:** capabilities are account-scoped (profile, history, per-player achievements) or global (economy, achievement catalogue, weather); identity differs per game; four authentication shapes exist (none, operator header key, operator Steam key plus the player's privacy setting, per-user OAuth with an approved application); and a ladder or rank-board capability exists in two sources but not in the current capability set.

## 3. Findings

Evidence tiers: **consensus** (standard or multiple independent credible sources), **practice** (what mature code visibly does), **single source** (the provider's own page or code for its own behaviour), **observed** (a live keyless call made on the date read), **unverified** (a claim whose host could not be opened).

### 3.1 Weather: Open-Meteo forecast API

- **Free tier, limits, non-commercial.** The terms page lists "Less than 10'000 API calls per day, 5'000 per hour and 600 per minute." and "You may only use the free API services for non-commercial purposes." Commercial use is "Websites or apps that have subscriptions or display advertisements."; non-commercial examples include "Private or non-profit websites or apps that do not have subscriptions or advertising." and "Voluntary donations, including contributions through a tip jar, are permitted." Tier: single source (the provider's terms page, read live 2026-10-20 and at the website pin `7083376`). The server enforces the same figures as defaults (`CALL_LIMIT_DAILY` 10,000, `CALL_LIMIT_HOURLY` 5,000, `CALL_LIMIT_MINUTELY` 600 in `RateLimiter.swift`).
- **Counted per IP and per application.** "Rate limits are applied by IP addresses and application." Shared hosts (Vercel, Netlify, Render, Google Sheets are named) "might be rate-limited earlier". Over a limit the server answers HTTP 429 with a reason string such as "Daily API request limit exceeded. Please try again tomorrow." (`RateLimitError.reason`). Tier: single source.
- **No quota header.** A normal forecast call (`/v1/forecast`, `current` and `daily`, 3 days) returned status 200 with only `Date`, `Content-Type`, `Transfer-Encoding` and `Connection` headers: no `X-RateLimit-*`, no `Retry-After`, no `Cache-Control`. A client therefore has to budget by its own count, not by a server hint. Tier: observed (2026-10-20); a 429 was deliberately not provoked.
- **Calls are weighted, not flat.** `calculateQueryWeight` documents "14 days of data are considered a weight of 1" and "10 weather variables are a weight of 1", scaled linearly, times the number of locations. Tier: single source (server code comment).
- **Licence and attribution.** The live licence page: "API data are offered under Attribution 4.0 International (CC BY 4.0)", "You must give appropriate credit, provide a link to the licence, and indicate if changes were made.", "You must include a link next to any location Open-Meteo data are displayed", with the example `<a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>`. Its data-source list includes "Location database from GeoNames ( CC-BY Licence )". Unit conversion and rounding are the changes a bot makes. Tier: single source. The geocoding repository README's line "API data are offered under Attribution-NonCommercial 4.0 International (CC BY-NC 4.0)" is not what the live licence page says; the live page governs, and in either case a non-commercial bot is inside the terms.
- **Not versioned as a product, but additive.** Path `/v1/forecast`; the geocoding docs promise "no required parameters will be added in the future" (docs page). No SLA ("All data is provided as-is without any warranty."). Open-Meteo is a community and commercial hybrid, not a government service. Tier: single source.
- **Request and response shape.** Observed response for `latitude`, `longitude`, `current=temperature_2m,weather_code,wind_speed_10m`, `daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max`, `forecast_days=3`, `timezone=auto`: top-level `latitude`, `longitude`, `utc_offset_seconds`, `timezone`, `elevation`; `current_units` and a `current` object (`time`, `interval` 900, scalar variables); `daily_units` and a `daily` object of parallel arrays (`time` plus one array per variable). Parameter list from the provider's OpenAPI file (`static/docs/openapi/forecast.yml` at the pin): `forecast_days` (default 7, maximum 16), `timezone` ("Any IANA time zone name is supported. Use auto to resolve the local time zone."), `temperature_unit` (`celsius`, `fahrenheit`), `wind_speed_unit` (`kmh`, `ms`, `mph`, `kn`), `precipitation_unit` (`mm`, `inch`); errors are `{"error": true, "reason": "..."}`; `weather_code` follows WMO. Tier: observed plus single source.
- **Cadence.** "Weather model updates every hour for Europe and North America" (server README), and the observed `current.interval` is 900 seconds, so a cache time of 10 to 15 minutes for current conditions is a judgement, not a documented figure.

### 3.2 Weather: geocoding

- **Open-Meteo geocoding** (`https://geocoding-api.open-meteo.com/v1/search`, same terms and fair-use line as the forecast API). Parameters (live docs page): `name` ("Location name or postal code. Append a country or first-level administrative area after a comma to narrow the results."), `count` (default 10, up to 100, "Country and administrative-area filters are applied before the result limit."), `language`, `countryCode` (ISO 3166-1 alpha-2), `format`. Matching: "Two characters match an exact name. Three or more use normalized prefix matching."; the qualifier "must match exactly; partial and prefix matching are not supported" (for example `Los Angeles, CA` or `Paris, France`). A result has `id`, `name`, `latitude`, `longitude`, `elevation`, `feature_code`, `country_code`, `admin1` to `admin4`, `timezone`, `population`, `postcodes`, `country`. Data comes from GeoNames. Tier: single source.
- **Observed behaviour, 2026-10-20** (first result unless stated; `count` 3 to 10):

  | `94105` | San Francisco, California, US; then Saint-Maur-des-Fossés, FR |
  | `75001` | Paris, FR; then Addison, Texas, US; then Paris 01 Louvre, FR |

  Reading: ordering is by relevance with population as the dominant factor (Illinois ahead of the larger-by-population Massachusetts shows it is not a strict sort), so a bare ambiguous name needs a disambiguation step; postal codes resolve to a town centroid, not to the code's area; and postal coverage is not uniform (US and FR work, UK full codes, one German code and one Canadian FSA did not). A bare postal code collides across countries. Tier: observed.
- **Zippopotam.us (fallback candidate).** `https://api.zippopotam.us/{country}/{postalCode}` with the country in the path (observed: `/us/90210` returns Beverly Hills, `/gb/SW1A` returns Westminster Abbey, `/de/10115` returns Berlin; response headers include `access-control-allow-origin: *` and `Cache-Control: max-age=14400`). The site says "Unrestricted No hard limits or restrictions of any kind. All at no cost." and "Data adapted from the fine folks at geonames.org"; it lists "Over 60 Countries Supported" with a code range and count per country. It publishes no terms, SLA or attribution rule. Tier: single source plus observed. It resolves the country-explicit postal case that Open-Meteo misses, but its lack of any stated terms makes it a fallback behind the same geocoder port, not the default.
- **Nominatim (OpenStreetMap), comparison only.** The usage policy: "No heavy uses (an absolute maximum of 1 request per second)."; "Provide a valid HTTP Referer or User-Agent identifying the application (stock User-Agents as set by http libraries will not do)."; "Clearly display attribution as suitable for your medium."; periodic requests from apps are "considered bulk geocoding and as such are strongly discouraged"; results "must be cached on your side". Tier: single source (policy page, read 2026-10-20). Not chosen: stricter limits and a bulk warning, and the policy requires that "switching should be possible without requiring a software update".
- **MET Norway and the NWS publish no geocoder.** MET Norway's FAQ: "You need a geocoding service." The NWS FAQ: "Our API does not offer a geocoding service." Tier: single source each.

### 3.3 Weather: other free no-key forecast services

- **MET Norway `api.met.no` Locationforecast 2.0** (`/weatherapi/locationforecast/2.0/compact?lat=&lon=`). No key. Live terms (`api.met.no/doc/TermsOfService`, revision dated 2020-06-26): an identifying User-Agent ("All requests must (if possible) include an identifying User Agent-string (UA) in the request"), with a contact address or website; "Anything over 20 requests/second per application (total, not per client) requires special agreement."; coordinates "truncate all coordinates to max 4 decimals" ("For new products, requests with 5+ decimals will return a 403 Forbidden."); honour `Expires`, use `If-Modified-Since`; throttling is HTTP 429; "fake or random strings as identification in the User-Agent header" earn "a permanent ban"; the live site warns that "Any requests with a prohibited or missing User-Agent will receive a 403 Forbidden error." Licence (`api.met.no/doc/License`): NLOD 2.0 with CC BY 4.0 credit, "Credit should be given to The Norwegian Meteorological Institute, shortened MET Norway, as the source of data." A service may not use "Yr" in its name. Tier: single source. Verdict: credible data, but it needs a separate geocoder, has stricter etiquette, and returns hourly series the bot would reduce to a daily forecast itself.
- **US National Weather Service `api.weather.gov`.** No key; requests need a `User-Agent` ("We recommend setting the value to something that identifies your application and includes a contact email"); "In the future we will replace the User-Agent requirement with a more typical API key system."; two calls per lookup (`/points`, then the grid forecast); US-only. A keyless `/points` call answered with JSON on 2026-10-20. Tier: single source (docs repository at `694ed0f`) plus observed. Not chosen: a public bot is not US-only.

### 3.4 Marvel Rivals

- **Official API: none.** `www.marvelrivals.com` (home page, read 2026-10-20) has no API or developer link in its markup, and `developer.marvelrivals.com` does not resolve (DNS failure from this machine). Tier: observed absence; it is not a statement from NetEase or Marvel.
- **Tracker Network.** `tracker.gg/developers` answered 403 with a Cloudflare challenge page ("Just a moment...") to a browser User-Agent. Unverified (source unreachable: `tracker.gg`). A search for an official or Tracker Network Marvel Rivals API returned none.
- **Community API `marvelrivalsapi.com`, from its documentation host `docs.marvelrivalsapi.com`** (an Apidog-hosted site; the endpoint pages carry "Modified at" stamps from 2025-07 to 2026-05-20).
  - **Unofficial status.** The Introduction ends: "The unofficial game API was not explicitly made usable by their entities for third parties and thus may be subject to change at any time. This project will be updated to reflect any changes to the data source." The Overview lists "A Discord bot" among the intended uses ("Whether you're building: A fan site, A Discord bot, Analytics tool, Or an internal tool").
  - **Authentication.** "All requests require a valid x-api-key header." The key comes from `marvelrivalsapi.com/dashboard/settings` (sign in, "Generate Key"). Base URLs are `https://marvelrivalsapi.com/api/v1` and `/api/v2`. Missing or invalid keys return 401.
  - **Rate limits.** "The Marvel Rivals API uses a dynamic rate limit that adjusts to each user and their usage"; headers `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; 429 on excess. No numeric figure on the pages read. The pricing page that search summaries quote (a free plan of 3,000 requests a day) is on the unreachable marketing host and is unverified.
  - **Player refresh.** `GET /api/v1/player/{query}/update`: "a QUEUE & TIME & USER sensitive / locked endpoint at a set time of 30 minutes ... it can only be used every 30 minutes on 1 specific player"; the update "can take up to 30 minutes ... In most cases though its done within 0 - 5 minutes"; repeat calls restart the queue place. So stats are a cached copy refreshed on request, not live.
  - **Endpoints and shapes** (from the endpoint pages' request and response examples): `GET /api/v1/find-player/{username}` returns `name` and `uid`; `GET /api/v1/player/{query}` (tagged "Free" and "Premium") and `GET /api/v2/player/{query}` (tagged "Premium" and "v2") take a UID or username and a `season` and return `uid`, `name`, an `updates` object (`info_update_time`, `last_history_update`, `last_inserted_match`, `last_update_request`), and `player` with `level`, `icon`, `team` and `info.rank_game_season`, a map keyed by season id whose entries carry `level`, `rank_score`, `max_level`, `max_rank_score`, `win_count`, `protect_score`, `diff_score`; `GET /api/v2/player/{query}/match-history` (filters `season`, `page`, `limit`, `skip`, `game_mode`, `timestamp`) returns `match_history[]` (`match_uid`, `match_map_id`, `match_play_duration`, `match_winner_side`, `mvp_uid`, `match_time_stamp`, `game_mode_id`, and a `match_player` block with `kills`, `deaths`, `assists`, `is_win`, `score_info` and `player_hero` stats) plus `pagination`; `GET /api/v1/match/{match_uid}` returns `match_details` with `match_players[]` (hero, kills, deaths, assists, damage, heal); `GET /api/v2/players/leaderboard` (`page`, `limit`, `device`, `season`) returns ranked players with a `rank` object; hero leaderboards, heroes, maps, items, patch notes, balances, seasons and achievements catalogues also exist. The docs do not define what "Premium" and "Free" mean on the endpoint pages; "Premium Images & Videos" are "Only available to Premium and Partner users."
  - **Identity.** "Searching player stats by username is a new feature and is not always reliable. Searching player stats by player uid is more stable."
  - **Stability.** v1 and v2 of the player and match-history routes coexist; the API ships "Community Libraries" (a Node.js wrapper and a typed JS library) and the docs say "We are working towards releasing official packages". Tier: single source. The documentation contains no terms of service, no attribution requirement, no caching or redistribution clause; whether such a page exists on `marvelrivalsapi.com` is unknown (502).
- **Wrapper evidence.** The Node wrapper (`MarvelRivalsAPI-Wrapper` @ `d6927e6`, request helper sends `x-api-key`; `matchhistory.js` documents `limit` "defaults to 40") and the Python wrapper (`externref/marvelrivalsapi` @ `edb7bf0`, `RankSeason` model) agree with the documentation's routes. Tier: practice.
- **Achievements are a catalogue.** `List achievements` and `Search achievement` take no player; they list what exists in the game. A per-player `ACHIEVEMENTS` capability is not backed. (The player object carries a `completed_achievements` count only.)
- **Where the data comes from is not stated.** The "update" queue suggests the service pulls from the game's backend on demand; that is an inference, not a documented fact, and the risk that upstream access changes is the provider's, not the library's.

### 3.5 Path of Exile 2

All GGG statements below are from `www.pathofexile.com/developer/docs` (pages `index`, `authorization`, `reference`, `changelog`), read 2026-10-20; the changelog's newest entry is "Updated 21/07/2026".

- **Registration is closed.** Under "Registering your Application" the page says: "We are currently unable to process new applications." Existing owners can still "manage applications owned by your account". Tier: single source (primary). So no new client id, scope grant or approved User-Agent identity can be obtained by this project today.
- **OAuth 2.1, two client types.** A *confidential client* is "backend by a secure server controlled by the application owner"; it may use any grant type, and "Any redirect URIs must point to a secure (HTTPS-enabled) URI with a registered domain controlled by the application owner. We cannot accept IP addresses or localhost domains even for in-development projects."; access tokens last 28 days and refresh tokens 90 days; rate limits are usually per client. A *public client* "Must only use the Authorization Code (with PKCE) grant type and must use a local redirect URI (ie. http://127.0.0.1:8080/callback)", "Cannot use any service:* scopes", gets 10-hour access tokens and 7-day refresh tokens, "shared rate-limits between all other public clients", and shows users an "authenticity ... unverifiable" warning. A web callback other than loopback is therefore allowed only for a confidential client on an HTTPS registered domain, which a Discord bot would have to host. Tier: single source.
- **Scopes and grants.** Account scopes (`account:profile`, `account:leagues`, `account:stashes`, `account:characters`, `account:league_accounts`, `account:item_filter`) need a per-user authorization-code grant. Service scopes (`service:leagues`, `service:leagues:ladder`, `service:pvp_matches`, `service:pvp_matches:ladder`, `service:psapi`, `service:cxapi`) "Requires a confidential client with the client_credentials grant type". Client-credentials tokens carry the application owner's identity: "tokens generated via the Client Credentials method have their identity set to the registered owner of the application." So a client-credentials grant does reach league and ladder data without a user, but only for an approved confidential client.
- **PoE 2 coverage.** The reference opens with "NOTE: There are currently limited APIs that return PoE2 game information." `realm` accepts `poe2` on `GET /league`, `GET /league/<league>` and `GET /league/<league>/ladder` ("Required scope: service:leagues:ladder"; the PoE1-only `sort` is marked); the ladder "only contains the top 15000 entries for PoE1, or the top 1000 entries for PoE2"; the changelog entry "PoE2 EA - 0.5.0" (updated 26/05/2026) says "The PoE2 Ladder endpoint is now enabled with the top 1000 entries available." Characters: `GET /character/poe2` and `GET /character/poe2/<name>` (scope `account:characters`; `realm` "can either be xbox , sony , or poe2"). Stashes, league accounts, guild stashes, public stashes, PvP matches and account leagues are PoE 1 only. A "Build Planner (PoE2 only)" section exists. So PoE 2 `PROFILE` (characters) and a ladder exist in the official API behind approval; match history does not exist for PoE 2. Tier: single source (primary).
- **Rate limits and stability.** "These limits are dynamic and can change at any time depending on our requirements." Responses carry `X-Rate-Limit-Policy`, `X-Rate-Limit-Rules`, `X-Rate-Limit-{rule}` (`max hits:period seconds:restriction seconds`), `X-Rate-Limit-{rule}-State` and, when exceeded, `Retry-After`; "Exceeding these limits frequently will result in your application access being revoked", and too many 4xx responses in a short period restricts the application. The introduction warns: "the details in this document may change without notice as we adjust to protect our backend from being overloaded. We make no guarantee of website uptime, or that API endpoints will remain available indefinitely." Tier: single source.
- **User-Agent and notice.** "Any application that interacts with our API must set an identifiable User Agent header prefixed using the following format: User-Agent: OAuth {$clientId}/{$version} (contact: {$contact}) ..." and "Every public or widely available application should include some form of the following statement in a visible location: This product isn't affiliated with or endorsed by Grinding Gear Games in any way." The page also says "we cannot allow our Intellectual Property to be used to generate commercial revenue" and warns against reverse-engineering endpoints outside the reference. Tier: single source.

## 4. How comparable projects do it

- **Wrapper libraries as the de facto provider API.** `MarvelRivalsAPI-Wrapper` (Node) exposes one class per endpoint family (`playerStats`, `matchStats`, `heroes`, `matchHistory`, `patchNotes`, `achievements`) over a single `makeRequest(url, params, body, method, apiKey)`; the Python wrapper has sync and async clients and typed `Model` classes (`RankSeason`, `PlayerInfo`, `LeaderboardPlayer`). Both inject the operator key as `x-api-key`; v1 and v2 are separate classes.
- **PoE 2 tools split data by source, not by game.** `poe2-mcp` combines GGG OAuth (`src/adapters/ggg-api.ts` targets `GET /character/poe2` with scopes `account:profile` and `account:characters`), poe.ninja data and Path of Building exports, and records that OAuth is the only blocked path. A second project (`poe-ninja-build-cost`) calls only the documented economy routes and reads profile data from a page the user already has open, to avoid the unsupported endpoints.
- **Open-Meteo consumers** call the forecast API with `latitude` and `longitude` from the geocoder; the geocoder's `countryCode` and `, <admin1>` qualifier are the documented ambiguity controls. MET Norway's terms describe a complete client lifecycle (identify, honour `Expires`, `If-Modified-Since`, store `Last-Modified`) that maps onto a cache with per-entry expiry.
- **Multi-game stat bots.** No open-source multi-game Discord stats bot with a provider abstraction was found; the provider shape here is derived from the sources' differences, not copied.
- **Old code in this repo.** GKB2's `WeatherCommand` and `Converter` read `res/zip codes.txt` on every call (`readLines()` of the whole file, `startsWith` for ZIP, `contains` for city, first hit wins), reply with raw latitude and longitude and never call a forecast API. The replacement is a geocoder plus a forecast provider.

## 5. Pitfalls and regrets

- **Open-Meteo's free tier is non-commercial by definition.** A subscription, premium tier or advertising on the bot's output puts it in the commercial category; keep the base URL and an optional key configurable (the paid host is `customer-api.open-meteo.com`, named in the OpenAPI file and the geocoding docs) so a commercial deployment can switch without code changes. Donations and a tip jar are allowed.
- **Per-IP counting, no quota header.** A bot behind a shared outbound IP shares the quota and receives no header telling it how much is left. Count calls locally, cache geocodes for days and forecasts for minutes.
- **Weights, not calls.** Many variables or a long range raise a request's weight above 1; a short forecast with fewer than 10 variables stays at 1.
- **City names are ambiguous.** The geocoder returns candidates ordered by relevance and population; the first hit for "Springfield" is Missouri. A bot that takes the first replicates the old `contains(...)[0]` bug. Offer a disambiguation (country, admin1) when the top results differ.
- **Postal codes are not uniformly covered and collide across countries.** `10001` matches a New York place first, then Spanish and French towns; `10115` finds no German hit; UK full postcodes find nothing. Ask for a country with a postal code, and report "no match" instead of a wrong place. Postal results are town centroids.
- **MET Norway blocks silently.** A missing or faked User-Agent gets 403 or a permanent ban; coordinates with five or more decimals are refused. If it is ever added, the transport needs per-host User-Agent and coordinate truncation.
- **Community API churn (Marvel Rivals).** v1 and v2 coexist, username lookup is flagged unreliable, "Premium" tagging is undefined, terms are unread, and the upstream is undocumented. The refresh endpoint's 30-minute lock and queue behaviour means data can lag and repeat refreshes make it worse; a tracker loop would multiply calls against a shared key.
- **GGG documents instability and has closed registration.** "May change without notice"; "We are currently unable to process new applications."; per-user OAuth for accounts; confidential-client web hosting for service scopes. A PoE 2 profile or ladder feature built now would be built on access that cannot be obtained.
- **poe.ninja "supported" is not stable.** "Allowed but incidental", no versioning, no SLA; route and parameter names for PoE 2 have to be taken from its page and re-checked, and the stash and exchange response shapes differ between PoE 1 and PoE 2. Excess use "will be blocked", with no stated number.
- **GGG's public currency feed is history, not a price.** It lags to the previous hour, is paged by `next_change_id` from the first hour of history, and old entries may be removed.
- **Steam privacy and the key.** Per-user Steam calls return nothing for profiles with private game details; show "make Game details public", not an error. The key must stay out of background loops by the terms. Free-to-play playtime vanishes by default (`include_played_free_games`).
- **Do not claim achievements for Marvel Rivals** from a catalogue endpoint, or match history for No More Room in Hell from nothing.

## 6. Recommendation for this repo

**Weather.** Ship one weather plugin with two ports and Open-Meteo as the default implementation of both: a `Geocoder` (query string plus optional country and language, returning candidate places with coordinates, timezone, country, admin1) and a `WeatherProvider` (coordinates plus units, returning a typed current-conditions object and a 5-day daily list). Request `current` and `daily` in one call (about 8 current and 6 daily variables, weight 1), `timezone=auto`, `forecast_days=5`, and let the guild or user choose units, which the API converts. Wire types are `internal @Serializable` with parallel `List<Double?>` arrays zipped into domain objects and `ignoreUnknownKeys`; a `WeatherCode` sealed hierarchy maps WMO codes to a description and an emoji, with an `Unknown(code)` case. Lookups that can miss return `Result` with distinct failures: `NoMatch`, `Ambiguous(candidates)`, `RateLimited(pause)`, `UpstreamError`. Cache geocodes for days and forecasts for 10 to 15 minutes, behind the shared per-provider budget (Open-Meteo sends no quota header, so the budget is local). Credit "Weather data by Open-Meteo.com" as a link in the embed author line (with `url`) or the description, and name Open-Meteo and GeoNames in the privacy policy. Keep the base URL and optional key configurable for a deployment that ever becomes commercial. Ship `getcity` and `getzip` as `!` aliases onto one `weather` command that takes a name or a postal code with an optional country (`weather 75001 fr`). For a postal code with a country that Open-Meteo does not resolve (UK, Germany, Canada were observed to fail), add a `Geocoder` implementation over `api.zippopotam.us` behind the same port, tried only after Open-Meteo returns no match; it needs the country, so the command asks for one when a bare code is ambiguous. Reject MET Norway and the NWS for the first release: MET needs a separate geocoder and stricter etiquette, and the NWS is US-only. The obvious option of keeping a bundled zip file is rejected: it is US-only, 4 MB, and read in full on every call.

**Marvel Rivals provider (its own phase, Experimental).** `MarvelRivalsProvider` over the community API with the operator key supplied through configuration, claiming `PROFILE` (with rank from `info.rank_game_season`), `MATCH_HISTORY` and `MATCH_DETAIL`, and nothing else; identify players by UID and use the username lookup only to resolve a UID once at link time. Keep it on demand: the refresh endpoint is locked for 30 minutes per player and the key's limits are unmeasured, so automatic match posts are not offered. The phase's first task is to reach `marvelrivalsapi.com` (pricing and terms), generate a key and confirm what the "Free" and "Premium" tags gate before any code. The privacy policy names this third party. No official source exists, so it is isolated behind the provider SPI so it can be replaced or dropped.

**Path of Exile 2 provider.** `ECONOMY` only, from poe.ninja's documented economy endpoints (`/poe2/api/economy/leagues`, exchange overview for currency-like categories, stash item overview for uniques), with a descriptive ASCII User-Agent and contact, conditional requests on `etag`, a cache of at least the documented 5 minutes (data refreshes about hourly for PoE 2), and a conservative local budget because no numeric limit exists. The capability needs no account link. GGG's public Currency Exchange CDN feed is a second documented, keyless economy source (currency pairs only, hourly history); it is worth modelling `EconomySource` as an interface so that the feed can back the same `ECONOMY` capability if poe.ninja withdraws access, but it is not needed for the first PoE 2 release. Plan `PROFILE` (`/character/poe2`) and a ladder capability only if GGG reopens registration and a confidential client with an HTTPS callback exists; that is not scheduled and should shape the 1.0 SPI only by allowing a capability that needs no link and a different authentication scheme.

**No More Room in Hell provider.** Steam-based, requires an operator Steam key (the provider registers only when a key is configured), claims `PROFILE` (persona from `GetPlayerSummaries`, playtime from `GetOwnedGames` with `appids_filter=224260` and `include_played_free_games`) and `ACHIEVEMENTS` (`GetPlayerAchievements` merged with `GetSchemaForGame` and the keyless global percentages), plus a stats subcommand only if the schema shows game stats (to be checked with the key at that phase). It does not claim match history, match detail or economy, and runs on commands only. Reuse Dota 2's Steam64 `AccountRef` for the link with the same optional-vanity rule. The privacy policy names Steam/Valve and the stored data; the bot states it is not affiliated with Valve.

**Shape the provider model has to take.** Four things differ across these sources and the model must not hard-code Dota's answer: (1) a capability is account-scoped or global, so `ECONOMY` (PoE 2), weather and the achievement catalogue need no link while `PROFILE` does; (2) account identity is a sealed set (Steam64, Marvel Rivals UID with optional username, PoE account name with discriminator), validated by the provider that owns it; (3) authentication is per provider (none, operator header key, operator Steam key, per-user OAuth with an approved application), and a provider that cannot be authenticated at start-up is simply not registered; (4) several sources have a season or league dimension (Marvel Rivals `season`, PoE league), so a capability call carries an optional season/league parameter. If a ladder or rank-board subcommand is wanted, the capability set needs a `LADDER` member, because two sources (GGG's ladder, Marvel Rivals' player and hero leaderboards) offer it and no current member covers it.

## 8. Gaps

1. **Marvel Rivals community API: pricing, free-tier size and terms of service (does not block the design; blocks the Marvel Rivals phase's budget model).** `marvelrivalsapi.com` answered HTTP 502 on every path tried on 2026-10-20 (`/`, `/pricing`, `/terms`, `/privacy`, `/api/v1/maps`, and the `www` host), and the Wayback Machine refused automated access, so the plan table (a free tier of 3,000 requests a day appeared in search summaries), the numeric rate limit, any terms of service and any attribution, caching or redistribution clause are unread. The documentation host has no terms page. What "Free" and "Premium" tags on endpoint pages gate is not defined there.
2. **Tracker Network.** `tracker.gg/developers` returned a Cloudflare challenge (403); whether it lists a Marvel Rivals API is unverified. Source unreachable: `tracker.gg`.
3. **Marvel Rivals upstream and freshness.** Where `marvelrivalsapi.com` gets its data is undocumented, and response shapes were taken from documentation examples, not from live calls (no key was created). Source unreachable for the API itself: `marvelrivalsapi.com`.
4. **GGG PoE 2 specifics that need an approved application.** Registration is closed, so scope grants, the actual rate-limit values per policy (`ladder-view` and others), the client-credentials ladder response and the User-Agent acceptance rule were read from documentation only. Whether and when GGG reopens registration is unknown.
5. **poe.ninja numeric limits.** None is published. The route names and category values were read from its page and verified only for `/poe2/api/economy/leagues` and one `exchange/current/overview` call; the stash item overview route for PoE 2 and its response were not called. Stability of routes beyond "best effort" is unknown.
6. **GGG public currency feed in depth.** Only the first-hour request was made; the walk to current hours, response sizes, the CDN refresh cadence and the pair-to-price conversion were not exercised.
7. **No More Room in Hell stats.** Whether the game defines Steam stats beyond achievements is not established (`GetSchemaForGame` and `GetUserStatsForGame` need a key, and `GetGlobalStatsForGame` needs a publisher key). Behaviour for private profiles (the exact error or empty body per method) was not observed; only Valve's reference wording on visibility was read. Valve's wiki (`developer.valvesoftware.com`) was unreachable (Anubis challenge). The key registration page (`steamcommunity.com/dev/apikey`) needs a login and any condition on new or limited accounts was not read.
8. **Open-Meteo geocoder coverage is sampled, not mapped.** Ten queries across US, FR, GB, DE and CA were tried; the set of countries whose postal codes resolve was not enumerated, and result ordering was observed, not documented. The geocoding repository README's CC BY-NC line was not reconciled with the maintainers; the live licence page (CC BY 4.0, GeoNames CC-BY) was taken as authoritative. GeoNames' own credit wording was not read beyond that licence-page line.
9. **Zippopotam.us** publishes no terms, SLA or limits beyond "No hard limits"; the project's long-term availability is unknown, which is why it stays a fallback.
10. **MET Norway** terms were read live, but the Locationforecast version in service and the privacy section were not checked; not recommended, so low impact.
11. **PoE 2 wiki and game-data sources** (`www.poewiki.net`, `poedb.tw`, PoE 2 wiki sites) were not researched; the old command's wiki lookup has no replacement identified.
12. **Multi-game stat bots.** No open-source multi-game Discord stats bot with a provider abstraction was found; the "best systems" lens rests on the wrapper libraries and the single-game bots named above.
13. **Budget numbers.** No calls-per-tracked-account model is computed for Marvel Rivals; it would reuse the Dota 2 file's arithmetic once the real limit is known.
14. **Discord footer markdown.** The Discord reference does not say whether embed footers render markdown links; this report relies only on the documented author `url` and the description or field values.
